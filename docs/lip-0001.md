# LIP-0001 metadata implementation

Components use the existing `Metadata` trait. `MemoryMetadata` and
`OxiaMetadata` implement the same validated operations; Oxia is the deployment
default. This replaces the old name-scoped database/schema/secret API directly.
There is no migration or compatibility reader for that layout.

| Key | Protobuf value | Oxia partition |
| --- | --- | --- |
| `/catalog` | `Instance { optional bool initialized = 1 }` | `catalog` |
| `/catalog/users/<name-key>` | `User { name, password_verifier, id }` | `catalog` |
| `/catalog/databases/<name-key>` | `Database { name, owner_user_id, allow_connections, connection_limit, state, id }` | `catalog` |
| `/catalog/allocator/user` | `Allocator { last_allocated }` | `catalog` |
| `/catalog/allocator/database` | `Allocator { last_allocated }` | `catalog` |
| `/discovery/<component-type>/instances/<uuid>` | empty `ComponentRegistration {}` | `discovery/<component-type>` |

The complete wire contract is [pb_meta.proto](../proto/pb_meta.proto).
Names are SQL-canonicalized before Meta receives them. `name-key` is lowercase
hexadecimal encoding of the exact UTF-8 bytes, preventing path/escape aliases
while preserving quoted case and Unicode. For example, `public` is
`/catalog/databases/7075626c6963`.

IDs are independent, nonzero uint32 values stored in the object. Each durable
per-type allocator is advanced by version CAS before a create-if-absent object
write. Gaps are allowed; counters never decrease or disappear on deletion.
Only a confirmed CAS returns an ID. Ambiguous/cancelled allocations poison that
writer; a high-water read cannot identify which concurrent caller committed it.
After restart, a fresh allocation advances the existing counter. Missing,
exhausted, or corrupt counters fail closed instead of resetting.

No tombstones, schema records, secrets, endpoints, or recovery jobs are added.
Registration UUIDs come from Meta.

## Review decisions

The implementation adds three minimal database fields needed by the agreed
behavior: optional `allow_connections` (absent means true), optional signed
`connection_limit` (absent means -1; zero is meaningful), and
`READY / DROPPING / DROP_FAILED` state. These additions are explicitly for review
alongside the implementation; the earlier two-field proposal cannot persist
connection controls or terminal failure state.

`initialize` claims `initialized=false` with create-if-absent, creates both allocators at zero, writes user
`lyrasys` and databases `lyrasys`/`public`, validates inventory, then publishes
`true` conditionally. A completed init is non-mutating on repetition.
An interrupted/ambiguous init fails closed: no resume, password replacement,
automatic repair, or reset command. `public` is not required or recreated after
successful initialization. The system database and user are protected.

Name uniqueness is enforced by the primary key's create-if-absent condition,
including between independent clients. Names and IDs are immutable through
direct Meta updates. Lookup by ID scans the small typed inventory for v1;
there is no additional reverse mapping or secondary index to keep consistent.
Duplicate IDs and key/value mismatches fail integrity validation.

This does not make Catalog admission/drop coordination distributed: that
lifecycle boundary still requires one Catalog writer until coordinated serving
is implemented. General user SQL/deletion remains deferred; the low-level user
delete API is not a multi-writer authorization or referential-integrity claim.

An ambiguous write is reconciled by confirmed value/version state, never
by returning an unconfirmed counter allocation. Unresolved or cancelled writes
block further mutations on that writer. This is conservative process-local
containment, not a durable exactly-once journal. Restart validation does not
magically prove a previously timed-out request never executed.

SCRAM-SHA-256 stores an 18-byte random salt, 4096 iterations, and 32-byte StoredKey
and ServerKey; no plaintext or SaltedPassword is stored. Public user inventory
contains only the name and value-stored ID. Authentication has a separate
verifier lookup. User/verifier Debug output is redacted. SQL administration,
roles, and privileges are deferred to future proposals.

Each registration owns a dedicated Oxia session. Explicit unregister, Drop, or
server session expiry remove that incarnation without closing the durable
client or another registration. Discovery is presence only, not routing,
readiness metadata, election, or fencing.

## Validation

`cargo test --all-targets` covers the production MemoryMetadata contract,
protobuf tags, redaction, production OTel instruments, and fault injection for
lost replies and cancelled writes. No test-only reference implementation is used.

`OXIA_BIN=/path/to/oxia bash scripts/test-lip-0001.sh` starts a fresh two-shard
Oxia server and runs the production OxiaMetadata contract, key/value
corruption checks, concurrent independent clients, durable per-type allocators, conditional writes,
physical deletion, lifecycle validation, and real process-death lease expiry.
It refuses occupied test ports and retains its isolated data/log directory.
PR CI downloads the checksum-pinned 0.17.1 release.

Oxia's deleted-tail sequence behavior is no longer used for object IDs. The
new contract asserts strict ID increase after deletion for both users and
databases; it does not claim an upstream Oxia sequence fix.

The library accepts an OTel meter and never installs a global provider. The
Catalog binary owns the direct Prometheus endpoint; HTTP/kind validation belongs
to Catalog, charts, and chaos, not these in-memory metric assertions.
